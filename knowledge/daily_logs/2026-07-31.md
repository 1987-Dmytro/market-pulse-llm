## Checkpoint — the precision constraint became a rule, not a value

Rev. 1 pre-registered "bf16 on a rented A6000" so all candidates would share one precision. That
value is not reachable on third-party endpoints: most cheap OpenRouter providers serve **fp8**,
several report `unknown`, and bf16 coverage is uneven across the three candidates. Rather than
pick a precision blind — or, worse, pick one after seeing accuracy — the constraint was rewritten
as a **rule fixed before any number exists**:

> Probe `GET /api/v1/models/<slug>/endpoints` for all three candidates first. If `bf16` is offered
> for all three, use bf16. Otherwise use `fp8` for all three. Never mix, never fall back silently.

Routing is pinned per request (`provider.order` with an explicit `<provider>/<variant>` slug,
`allow_fallbacks: false`, `quantizations: [...]`), and provider + quantization go into every
provenance record. OpenRouter does **not** return the endpoint's quantization in the response
body — `openrouter_metadata` (opt-in header, marked experimental) carries a provider display name
only — so the request config is the ground truth to log, joined against an endpoints snapshot
taken at run time.

The honest caveat is that these numbers come from third-party serving, not our hardware. It is
paid off, not waved away: the model chosen at the Phase-4 gate gets **one zero-shot re-run on our
own pod during the Phase-4 smoke** as a cross-check. Recorded in the ADR the executor writes as
task 1 of the rewritten prompt.

**Candidates are now fixed by the operator** (live search done today, executor must not
re-select): `google/gemma-4-31b-it` (~31B, Gemma Terms of Use), `qwen/qwen3.6-27b` (~27B,
Apache-2.0), `qwen/qwen3.5-9b` (~9B, Apache-2.0, the cheap floor that answers "is a small model
enough"). Both large ones shipped April 2026, so the SPEC §7 list (Qwen3-8B/14B, Llama-3.1-8B,

## Checkpoint — a new Phase-4 fork, raised by the operator

Asking "can we adapt the unquantized base?", the operator independently arrived at **plain LoRA** —
the "Q" in QLoRA is only the quantization of the frozen base. It is a real option and it is now a
recorded deferred decision rather than an assumption.

VRAM (base + adapters + activations): Gemma-4-31B ~70 GB bf16 / ~24 GB 4-bit · Qwen3.6-27B ~62 /
~21 · **Qwen3.5-9B ~22 / ~8 — bf16 fits a 48 GB A6000.** So branch (1), no quantization anywhere,
is live and depends on which model wins 3b.

**Training cost is explicitly disqualified as the deciding argument.** The dataset is ~2 950 short
rows; a run is 1–1.5 h; QLoRA on A6000 ($0.53/h) versus bf16 LoRA on A100-80 ($1.39/h) differ by
single dollars. The criterion recorded instead is **train in the precision you serve**, understood
as a distance scale rather than a binary: bf16 → fp8 is a short hop needing no special treatment
(which is why ordinary LoRA is fine when production runs fp8), while bf16 → 4-bit is far enough
that the adapter must be trained against the quantized base — that is precisely what QLoRA is for.
Three branches and the full rationale are in `docs/STATUS.md`.

## Checkpoint — two reporting bugs found by the operator's questions

Both came out of a long explanatory thread, not from an audit, and both were fixed in
`aae7b8f` before the step launched. Worth noting as a process observation: **the operator asking
"I don't understand" twice was more productive than the last checklist pass.**

1. **XLM-R gate coverage.** XLM-R is a classifier; G1e brand extraction is a span/NER task. Left
   alone, its row would carry a blank G1e cell that reads as "scored badly" when it means "never
   attempted" — a comparison-table corruption of exactly the kind the honesty rules exist to catch.
   The prompt now demands explicit per-gate coverage in the report.
2. **Adapter-merge drift.** An adapter trained against a 4-bit NF4 base compensates *that base's*
   quantization error; merged into bf16 weights it corrects errors that are no longer present.
   Second-order but measurable, so it is measured: the artefact is scored in the exact
   configuration that will serve production, and the safe default is to serve the 4-bit base with
   the adapter unmerged. Recorded as a Phase-5 footgun in [[hot]].
