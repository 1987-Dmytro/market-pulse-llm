### 1.2 The matcher: one implementation, opt-in, carrier-scoped

`src/market_pulse/brands.py` gained `load_watchlist_rules` / `WatchlistRules` and a third parameter
on `find_watchlist_brands`. Three properties, each load-bearing:

1. **A rule can only REMOVE.** It is a requirement on a hit the alias table already made. Nothing in
   the file adds a name or a spelling, which is what keeps a revision from being a quiet registry
   edit. Asserted from the database side too:
   `test_the_revision_lives_beside_the_anchor_matching_and_not_on_top_of_it` checks that every r1
   row exists in the anchor table.
2. **It is off by default.** `find_watchlist_brands(text, aliases)` matches exactly what it matched

   sha-pinned by two sealed records and cannot be edited to opt into the old behaviour, so the old
   behaviour has to be the default.
3. **The rules travel with a `carrier`.** 3.21 (1) scopes the `garmonija` rule to comment text, and
   a scope the caller never states is a scope nothing can check — so `rules` without `carrier` is a

different numbers: 35 is "how many leaves the matcher feeds", 12 is "how many the revision changes".

**The split.** Two TABLES, not a `rules` column on one. With a column every existing query becomes
wrong-by-default until somebody remembers a filter; with two tables the convergence path's SQL is
character-for-character the same SQL, and that is checkable with `git diff` instead of with an
argument about filters. `aggregates.mirror()` is untouched.

**The unit exists.** All 514 threads join to `data/raw/posts` — 5 075 of 5 075 comments, zero

needed the cast: the raw store writes `msg_id` as a string.)

**The price is an interval, not a rate.** `results/run_5c2_comments.json` measured **4.247 s per
COMMENT row** at $0.00030669/s, over 5 078 rows in 55 calls on endpoint `gfmtqi3uqcjyv5`. The plan's
step C is one call per THREAD — different input, different output, a different job. So each cell
carries both ends and says which is which: lower = a thread call costs one comment call; upper = it
costs as much as reading its comments one by one. Beside every price, its sample
(`.claude/rules/registrations-and-draws.md`, read by hand — its `paths:` globs do not match a census
script, so it did not inject). **Dv360.**

**The fourth silencer has no input.** `giveaway_threads` reads the model's post-type label, and

(`positions_text_gm4`, 44 rows over 10 channels) and its replies are position lists. Reporting

The record declares it unimplemented with its reason and its unlock, and says out loud that the
silencers-on cells are **three** silencers. **Dv361.**

**Each silencer also runs alone,** because kills can overlap and a 2×2 that only ran them as a set
would read as buckets it is not:

| silencer alone | threads removed | comments silenced (window-wide) |
|---|---|---|
| `varto_rule` | **18** | — |
| `plus_spam` | 0 | 110 |

Removed(all three) = Σ removed(singles) = 18, so nothing was removed twice in this window. Both

**The plan's own numbers, against the measurement.** `docs/PLAN-comment-signals.md` §2 C and §6 say
