## 4. Stop-points — and the forks that are NOT stops (decide, name it in PROGRESS, continue)

1. Any paid or irreversible step: a pod/serverless/template create, a `firebase deploy`, a registry revision, a move of a sealed record — STOP (the operator's word). The loop daemon never creates anything; the endpoint field of `data/loop.json` is written by the operator alone.
2. A UI/design fork `docs/DESIGN-ship-1.md` does not settle → NOT a stop: the simplest reading that keeps every number from its file, named in PROGRESS with the line the brief lacks; the team lead revises the brief the same day.
3. A library choice the brief names is unavailable or broken at the pinned version → the nearest maintained version, pinned, named in PROGRESS — not a stop; a switch to ANOTHER library is a stop.
4. A test that pinned a literal of a record that legitimately moved (a window id, a row count, the default window) → rewritten to read the record, both directions, same commit (fork (e) of promo-pulse-1 §6.6) — not a stop; weakening an invariant stays a stop.
5. The harness's deny rules on team-lead paths reach into Bash file commands: read them with the Read tool; never `cat`/`sed`/`cp` a `docs/` team-lead path — a refusal met once is handled by the documented path, never by a series of probes (PROCESS «Harness fields»).
6. `make check` runs ≥ 12 min: run it ONCE at the end of an item (unit-test the touched files as you go); `npm run check` + `vitest` are the front's fast loop.
7. Money: $0 on every item; the guard's reading is read, never re-anchored; REMAINING $1.1602 is a display value, not a budget.
