# Taxonomy v2: what is prepared, what it costs, and what the corpus can still give

Phase 4.5d, 2026-08-02. `docs/SPEC.md` amendment 3.8 adds a sixth intent, **`service`**, and
pre-registers the work that follows: guideline v2, an intents re-label of the labelled data with
operator calibration, test v4, a fresh G1c anchor under a prompt that knows the sixth class, one
retrain, and new program bars registered before it is scored.

This step prepares that and decides nothing. The 4.5d gate decides the up-labelling appetite and
whether 4.5e starts. Everything below is either a measurement or arithmetic on one; the numbers
come from `results/relabel_probe_45d.json` and `results/uplabel_candidates.json` and are
regenerated by the two scripts named beside each table.

## The probe — 50 train rows, taxonomy v2

`scripts/relabel_intents.py --limit 50`, seed 42, `qwen/qwen3.6-27b` at the pinned fp8 endpoint,
intents column only. The model was chosen on the only measurement that exists for the job: intents
micro-F1 against human gold on the comment test set (3b) — 0.768 here, 0.774 for
`claude-haiku-4.5`, 0.798 for `gemma-4-31b-it`, and the last is the model under test, so gold made
by it would turn part of G1c into agreement with itself.

| measured | value |
|---|---|
| rows scored | 50 of 50, 0 unusable |
| intent set changed | 24 rows, 48% |
| ... changed **without** gaining `service` | 9 rows, 18% — drift v2 does not explain |
| rows carrying `service` | 15 rows, 30% |
| `service` replaced | `[]` ×12, `availability` ×2, `price` ×1 |
| cost | $0.0081, **$0.000162 per row** |

The first attempt lost 3 of 50 rows to replies of `{}` — the model's way of saying "no intents",
which the parser refuses rather than coerces. One clause was added to the re-label prompt (*always
write the `intents` key*) and the 50 rows were re-run: 0 unusable. Both runs are in the record with
their own prompt hashes.

## The corpus: what is left to label

`scripts/uplabel_candidates.py`. Counts and overlaps only; nothing here labels a row.

| step | rows |
|---|---|
| **corpus** | **11338** |
| no text (media only) | 4114 |

The thread exclusion is not bookkeeping: the comment split is by thread (`channel`,
`parent_msg_id`) so that no test row's thread-mate can be trained on, and an up-label pool feeds
training. A count that skipped it would offer 1,239 rows that may not legally be labelled.

| stratum | rows | heuristic |
|---|---|---|
| service-rich | 382 | UA+RU keywords, 6 groups |
| sarcasm-rich | 0 | `market_pulse.sarcasm` score >= 3 |
| ... any irony signal at all | 149 | score >= 1; the pool's highest is 1 |
| in both | 0 | — |
| general (neither) | 1530 | — |
| ... of which bot `+` markers | 4 | `unclear` by rule, never labelled |

**The corpus is mined out for sarcasm.** Not one row left in the pool scores 3 — the pair score the
mining rule calls a candidate — and the highest score anywhere in it is 1. Both waves took what was
there (`docs/frozen-testsets.md`: "only 89 of the 971 fire an irony heuristic at all"). More
sarcastic rows can only come from new collection or from generation, not from this corpus.

The keyword sweep is a ranking device, not a label: against the 50 re-labelled probe rows it finds
10 of the 15 rows a model called `service` (recall 67%) and 6 of its 16 hits were not (precision
62%). Fifty rows, so this is a caveat on the 382, not a validation of it.

| +2k | 2000 | 382 | 1618 | NO — 88 short, ~0.2 months |
| +5k | 5000 | 382 | 4618 | NO — 3088 short, ~7.0 months |

The two comment-bearing channels write ~805 comments a month (2026-04..06), of which ~55% survive
the exclusions a fresh month faces — about **443 labelable rows a month**. Only two registry
channels have comments enabled at all (`data/entry_check_report.json`), and both are backfilled to
their oldest reachable post, so that rate is the ceiling's speed. +2k is a fortnight of collection
away; +9k is a year and a third, or a new source.

## Calibration, at the pre-registered bar

SPEC §8 gates a label set on **≥90% agreement**, measured by re-reading *a random 100 rows*. The
sample is pre-registered and is not resized here — binomial precision depends on the sample, not on
the population, so 100 rows carry a ±5.9 pp 95% band around the bar whatever the batch size.

| calibration | rows to review | operator hours |
|---|---|---|
| re-label, gated sample | 100 | 0.7 |
| re-label, + changed-row diagnostic | 150 | 1.0 |
| up-label +2k, 3 strata | 300 | 2.0 |
| up-label +5k, 3 strata | 300 | 2.0 |
| up-label +9k, 3 strata | 300 | 2.0 |
| second round if a stratum misses | 100 | 0.7 |

Hours are verdict-style review at **150 rows/hour** (band 120–180): the operator is shown a label
and agrees or does not. The rate's provenance is this project — 244 blind verdicts in the 4.5a
audit in one sitting, and the team lead's 10–15 minute estimate for the 28-block law pack.

**The hours do not scale with the tier.** A bigger appetite buys rows, not review: the model
labels, the operator calibrates a fixed sample, and money is a rounding error at $0.00016 a row.
What a bigger tier costs is *risk* — a stratum that misses 90% sends its whole batch back, and the
batch is what got bigger.

## Open questions for the gate

1. **The re-label set is larger than the prompt says.** 2,746 = train + candidates + test. Another
   1,025 labelled comment rows carry an intents column: the 971-row wave-2 holdout pool (kept for
   error analysis and any future holdout extension) and the 54 holdout rows drawn from the
   candidates pool. Amendment 3.8 says "ALL labelled data". Re-labelling them costs $0.16 more;
   leaving them out means two taxonomies live in the same repo.
2. **Provenance of a re-labelled row.** The prompt says intents column only, so a re-labelled row
   still carries `annotator: "llm-precheck"` — the row cannot say who moved its intents, and only
   the record can. Test v3 took the opposite convention (`annotator: "operator-blind-audit-45a"`).
3. **The unexplained 18%.** Nearly a fifth of the probe rows changed inside the five old classes.
   That is the model disagreeing with the annotator, not the taxonomy moving, and it is the number
   the ≥90% calibration will be deciding on.
4. **`unclear` rows.** They carry intents and are excluded from every gate. Re-labelling them costs
   money and changes nothing that is scored; skipping them leaves the column mixed-taxonomy.
