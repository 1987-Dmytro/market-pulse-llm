## Разрывы (5 находок с доказательствами)

**1. Сигнал исполнителя не замыкается на процесс.** implementation-notes.md —
6 953 строки, 268 Dv-записей. Каждая фиксирует ЧТО отклонилось, ни одна —
системную причину (пробел контракта? спеки? окружение? модель?). Тимлид
читает Dv для приёмки сессии и никогда — как вход для правки скилла.
Самоулучшение скилла случается только при пойманных сбоях процесса
(аудиты 05.08, 09.08, 13.08) — реактивно, не систематически. Это и есть
ощущение «какой-то момент упускаем»: канал есть, замыкания нет.

**2. Скилл превращается в хронику.** 663 строки; инцидент 2026-08-13 упомянут
~8 раз в разных разделах; целые абзацы — пересказ кейсов (vis-b, Dv50,
srv-2b, carve-758) вместо дистиллированных правил. По ACE (Stanford, 2025)
это путь к деградации: контекст без периодической дистилляции теряет
сигнал в шуме. Скилл сам требует «keep the smallest set of high-signal
tokens» (Anthropic-1) и сам это правило нарушает. Каждый запрос тимлида
платит налог ~663 строк.

**3. Нет процедуры консолидации.** Meta-rule скилла требует править его «in
the SAME session» — правки добавляются, но ничего не сжимается и не
удаляется. Нет триггера («скилл больше N строк → дистилляция»), нет
процедуры (истории → принципы, кейсы → в vault проекта). Тот же паттерн
у STATUS.md: сжат 05.08 с 1 172 строк — сегодня снова 1 275 (ячейка
Phase 5 — нечитаемая простыня в одной ячейке таблицы). Правило компакции
есть, числового триггера нет — поэтому не срабатывает.

**4. Нет таксономии причин → нет трендов.** «Deviations-per-phase» объявлен
health-метрикой, но без классификации причин тренд ни о чём не говорит:
24 отклонения от «контракт перегружен» и 24 от «модель галлюцинирует
имена» требуют противоположных реакций. Нечего показать оператору как
«процесс стал лучше/хуже» между фазами.

**5. Уроки не маршрутизируются по домам.** Пойманный урок сейчас едет туда,
где его поймали: в скилл (если поймал тимлид) или в Dv-запись (если
исполнитель). Правильный дом определяется не местом поимки, а природой
урока: проектное правило → CLAUDE.md/rules, контрактный пробел → SPEC,
«должно происходить всегда» → hook, переносимый процесс-урок → скилл.
Без явной маршрутизации скилл собирает проектные детали (примеры выше),
а проект недополучает правила.

## Сверка с best practices (август 2026)

- **Karpathy (Sequoia Ascent 2026, «agentic engineering»):** 5 компетенций —
  spec design, diff review, eval design, security oversight, quality taste —
  в скилле отражены все. Разрыв не здесь.
- **Cherny 2026:** parallel worktrees, plan mode, «make sure Claude has a way
  to verify its work», vanilla setup — покрыто. Его акцент «модели уже можно
  доверять больше» поддерживает курс скилла Anthropic-6 (judgment over rules).
- **Anthropic 2026 — ключевая новинка: Claude Dreaming** (research preview):
  межсессионная консолидация памяти — процесс читает логи прошлых сессий +
  memory store, находит повторяющиеся паттерны и failure modes, переписывает
  память (дубли сливаются, противоречия разрешаются). Это подтверждение
  направления оператора: Anthropic строит ровно этот цикл, но как ОТДЕЛЬНЫЙ
  процесс между сессиями, а не как побочную задачу рабочей сессии.
- **ACE — Agentic Context Engineering (Stanford, arXiv 2510.04618):** научная
  рамка для идеи оператора. Три роли: Generator (исполняет, оставляет trace),
  Reflector (извлекает переносимые уроки из trace), Curator (вносит уроки
  МАЛЕНЬКИМИ ДЕЛЬТАМИ в плейбук). Два предостережения, критичных для нас:
  (1) полное переписывание плейбука ведёт к context collapse (в их замере
  рерайт схлопнул 18k токенов контекста в 122 и уронил точность 66.7→57.1);
  (2) рост без дистилляции хоронит сигнал. Отсюда: дельты, не рерайты;
  периодическая дистилляция, не непрерывное дописывание.

## Дизайн: Self-Improvement loop (внедрён в скилл 2026-08-13)

Роли ACE ложатся на нашу систему без новых сущностей:

| ACE | У нас | Что делает |
|---|---|---|
| Generator | Исполнитель (Opus, Claude Code) | Работает; Dv-записи + новая секция Process signals в отчёте |
| Reflector | Тимлид на границе ФАЗЫ | Читает теги Dv за фазу, извлекает переносимые уроки |
| Curator | Тимлид + гейт оператора | Маленькие дельты в ПРАВИЛЬНЫЙ дом; оператор утверждает diff |

**Механика (три дельты к существующему процессу, ноль новых файлов):**

1. **Тег причины в Dv-записи.** Каждая Dv-запись заканчивается тегом:
   `[cause: contract-gap | spec-gap | env | tooling | model | process]`.
   Плюс отчёт сессии заканчивается секцией «Process signals» (≤5 строк):
   что тёрло в процессе, чего не хватало в контракте, что пришлось
   выяснять самостоятельно. Стоимость для исполнителя — минуты.
2. **Phase-boundary retro (новый пункт RECORD).** На закрытии фазы (не каждой
   сессии) тимлид агрегирует теги Dv фазы + Process signals и маршрутизирует
   уроки по домам: проектное правило (2-я встреча) → CLAUDE.md/rules;
   контрактный пробел → шаблон промпта или SPEC; «must happen every time» →
   hook; переносимый процесс-урок → скилл (последний резерв, самый дорогой
   дом). Сводка тегов — строка в STATUS при закрытии фазы (тренд для
   оператора).
3. **Delta discipline + консолидация скилла.** Правка скилла = правило-принцип
   (≤5 строк, максимум один пример), никогда нарратив. Триггер дистилляции:
   скилл > 700 строк ИЛИ один инцидент упомянут > 2 раз → отдельная сессия
   консолидации с оператором (истории сжимаются в принципы, кейсы уезжают в
   vault проекта). Diff скилла оператор видит ДО применения.

**Метрика замыкания:** повтор того же cause-тега в следующей фазе после
внесённой правки = правка не сработала → эскалация по лестнице детерминизма
(прозы → checklist → hook). Это «march of nines» применительно к самому
процессу.
