## 2. Что входит в скилл team-lead v3.1 (общие правила)

1. **Каталог развилок в шаблоне файла фазы** — четыре класса с ответом по умолчанию, записанные ДО первого пункта: валидность платного
   чтения (полный ран или «неполный», не сравнивается); второй экземпляр чего угодно (одно id на сущность, экран показывает все);
   рост пиннутой структуры (объявленный боковой файл, один читатель); пойманный дефект продукта (один тест в обе стороны, без авторизации).
2. **Триаж красного бара:** сначала полнота рана (каждая единица отвечена и распарсена), потом эталон и грейдер, только потом закон.
3. **Контракт промт ↔ транспорт:** всё, что промт разрешает (объект/массив, с ограждением/без), транспорт принимает — дрилл при $0 до первой
   покупки; форма, которую модель выдала позже, входит в дрилл один раз.
4. **Разбор паттерна при каждой остановке** (≤5 строк после рулинга): класс · предвидимо ли · какое правило входит и куда. Метрика ретро:
   «предвидимые остановки» — класс, встреченный дважды, становится правилом шаблона; правило, не сработавшее за фазу, удаляется на ретро.
5. Порог v3 «≤1 остановка/день» сегодня превышен (2). Ответ по метрике — диета, а не фича: закон исполнителя не вырос (+0 гардов, +0 тестов),
   выросли правила по умолчанию в файле фазы (+14 строк), которые снимают будущие остановки этих классов.

## 3. Дельты brain-init M6 (исполнительская сторона; применяет оператор в Claude Code)
- Продюсеры берут пути параметрами (`--out --channels --anchor --prereg --step --cap`); печать пиннит результаты, не путь кода.
- Раннер печатает `parse_failures` как гейт валидности рана; до первой покупки нового инструмента — дрилл форм ответа при $0.
- Запись открытого стопа в PROGRESS несёт строку `class:` (planned read · fork · defect · money · process) — метрика собирается из PROGRESS.
