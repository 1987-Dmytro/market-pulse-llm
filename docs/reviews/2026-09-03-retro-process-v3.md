данных (4, 5), либо закон о деньгах был написан по интуиции и опровергнут инструментом (1, 2, 3, 6, 8), либо закон нарезки
работы (6, 7). Каждый рулинг тимлида ОТВЕЧАЛ на паузу новыми инвариантами — и увеличивал закон, который породит следующую паузу.

## 3. Что говорят источники (сентябрь 2026) — и где мы разошлись

- **Anthropic, Best practices:** «Keep CLAUDE.md concise. For each line ask: would removing this cause Claude to make mistakes? If not,
  cut it. Bloated files cause Claude to ignore your actual instructions.» «If you could describe the diff in one sentence, skip the
  plan.» «Give Claude a check it can run.» «A clean session with a better prompt almost always outperforms a long session.»
  **Мы:** исполнитель читает в начале сессии ≈2 300 строк процессной прозы (CLAUDE.md 72 + rules 461 + hot.md 71 + PROCESS 149 +
  PHASE 109 + план ~700 + рулинги 611 + STATUS 189) — «bloated» на уровне выше CLAUDE.md.
- **Anthropic, `/goal`:** «one measurable end state, a stated check, constraints that matter»; оценщик — Haiku, читает только транскрипт,
  ничего не запускает; вердикты Met / Not yet met / Impossible; ветка «PAUSE, когда есть файл» — **не документирована**.
  **Мы:** предикат из 12 проверок + ритуал + ветка PAUSE + деньги (3 232 символа, две версии) — 27 холостых ходов и три вечера.
- **Anthropic, Effective harnesses for long-running agents:** список фич в JSON с полем `passes`, файл прогресса, свежая сессия читает
  git log + прогресс и берёт ОДНУ фичу; «работать над одной фичей за раз — критично против склонности агента делать слишком много».
  **Мы:** прогресс размазан по шести местам (STATUS, hot.md, daily log, STOP, report, рулинги); сессия 6 делала семь дел.
- **Karpathy (26.01.2026):** агенты «делают ложные допущения, не проверяют, переусложняют, пишут раздутый код»; лекарство —
  «не говори что делать, дай критерий успеха и смотри как ястреб». **Мы:** критерии успеха есть (грейдеры, бары) — это сильная
  сторона; но «переусложнение» мы не гасили, а ПООЩРЯЛИ: каждая пауза → новые пины, печати, рунги, тесты на прозу STATUS.
- **Karpathy, March of nines:** надёжность считается на ПРОДУКТЕ. **Мы:** 4 313 зелёных тестов и ни одного платного прогона
  сигнального слоя за четыре дня — надёжность процесса вместо надёжности продукта.

## 4. Ошибочные паттерны скилла team-lead v2.4 (мои, честно)

1. **Закон растёт, но никогда не убывает.** Есть принцип «guard once», нет запрета «рулинг не добавляет инвариантов». Итог — 15:1.
2. **Предикат как программа.** §5 требует «каждая проверка — команда и вывод», ветку PAUSE, ритуал, кап ходов — для оценщика,
   который читает только транскрипт. Инструмент не для этого.
3. **Артефакты процесса без потолка.** Отчёт ≤30 строк есть; рулинг, STOP, handoff, план — без потолка. Рулинги стали эссе по 60 строк,
   STOP — 12 КБ, за день — четыре handoff-а.
4. **Деньги как бюрократия.** Четыре рунга, шаг-леджеры, settlement с допуском, якоря — для шага в $2.50. Стоимость охраны в сессиях
   и паузах превысила охраняемую сумму в разы. Правильная охрана для таких сумм — платформенный `--terminate-after` от капа и один
   взгляд.
5. **«Query before contract» — принцип без механизма.** Я не спрашивал «кто читает файл» перед спекой второго окна (паузы 4, 5).
6. **Нарезка «одна фаза — один /goal»** хороша против кучи слайсов, но требует от сессии слишком многого; единица работы должна быть
   ОДИН пункт списка фич за сессию (Anthropic), а не «фаза до паузы».
7. **Тимлид как второй исполнитель.** Я пишу по 50 КБ прозы на паузу; исполнитель — по 12 КБ STOP; оператор читает и то и другое.
   Понимание оператора (§1 скилла) от этого не растёт, а тонет.

## 5. Что меняем — v3 (принципы; механика — PROCESS; исполнительская сторона — brain-init M6 v2)

1. **Один файл фазы, который читает исполнитель:** вопрос → артефакт → **список фич с полем `passes` и командой проверки на каждую**
   → ограничения → стоп-точки с таблицей решения → журнал решений (дата, ≤12 строк, решение — не закон). Потолок 150 строк.
2. **Один файл прогресса исполнителя** (`docs/plans/<phase>.PROGRESS.md`, ≤60 строк): сделано / следующий пункт / открытая стоп-точка.
   Заменяет STOP-файлы, отчёты, daily logs, hot.md-бюджет. Свежая сессия читает git log + прогресс + файл фазы и берёт ОДИН пункт.
3. **Без `/goal` для фаз со стоп-точками.** Стандартный промт запуска ≤12 строк, один и тот же каждую сессию; стоп-точка = запись в
   прогресс и конец хода. `/goal` — только для одной сессии с одним измеримым концом и без человеческого решения внутри.
4. **Диета закона:** рулинг решает и не законодательствует; новый тест — только на дефект продукта или инвариант данных; печати не
   пиннят растущие файлы; тесты не читают прозу; деньги = кап в `--terminate-after` + одна строка леджера на сессию; набор гардов
   заморожен на этап; метрики ретро (соотношение строк, доля процессных коммитов, паузы/день) — с порогами, при которых объявляется диета.
5. **Потолки процесса:** STATUS ≤60 строк = карта + финиш (handoff отдельным файлом не пишется); рулинг ≤12 строк; STOP ≤15 строк;
   брифинг шага ≤5 строк.
6. **Единица работы = один пункт списка фич за сессию исполнителя; приёмка — в тот же день; цель — ≥2 сессии в день, ≤1 пауза в день.**

Скилл team-lead v3 — отдельным драфтом на карточке (сохранить только после чтения); brain-init M6 v2 — список дельт в §6 этого файла.
