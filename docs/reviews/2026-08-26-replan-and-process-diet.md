## 5. Как работать дальше — диета процесса

Принцип (Anthropic, «effective harnesses for long-running agents»): **единица работы — видимый
пользователю артефакт из списка фич, одна фича на сессию, проверка end-to-end, git как память.**
У нас единицей стала «регистрация с рунгами» — это правильно для платных ранов и разрушительно
для всего остального.

1. **`docs/FEATURES-phase7.json`** — список A1–A6 (+B при рулинге): id · что · как проверить ·
   статус. Claude Code берёт одну фичу за сессию, коммитит, отмечает. Тимлид принимает, ОТКРЫВ
   артефакт (README, страницу демо, скриншот), а не перегоняя 10-минутную суиту: суиту гоняет
   исполнитель, тимлид читает stamped-вывод.
2. **Контракт ≤50 строк**: цель · фича · файлы · проверка · DO-NOT (3 строки: файлы тимлида,
   числа руками, `git add -A`). Без read-back на 14 чисел, без рунгов (кроме платных).
3. **Отчёт ≤80 строк**: что сделано · где лежит · доказательство (команда + вывод) · отклонения.
   Без чекера «своих чисел» на каждый отчёт, без ADR без решения, без вольт-хвоста как отдельного
   деливерабла (вольт живёт в `/save`).
4. **Платный контракт (если будет)**: кап = 2× оценки из реестра измерений; четыре рунга —
   цена при create · живость по последнему событию/`nvidia-smi` · проекция с **ASK-рунгом**
   (перерасход ≤20% → ≤10 мин на слово оператора в сессии, цитата в отчёте) · хард-стоп
   платформы. Не восемь.
5. **Ярус тимлида**: STATUS сжимается до ≤120 строк (миссия · DoD с галочками · деньги ·
   открытые решения; хроника — в git); хэндофф ≤30 строк; `results/measurements.jsonl` как реестр
   физических констант; скилл team-lead дистиллируется до ≤400 строк отдельной сессией
   (дельты из ретро 26.08 входят). Приёмка фичи — в тот же день, что и её отчёт.
6. **Правило суждения вместо десяти правил**: контракт называет пункт DoD, который продвигает;
   гейт называет потерю, которую предотвращает; число называет файл, откуда взято. Нет одного из
   трёх — не выдаётся.
