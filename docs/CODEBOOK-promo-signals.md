Читают одно и то же: эталон `docs/labels-promo-dev.jsonl` / `docs/labels-promo-holdout.jsonl`, промт исполнителя
для сигнального слоя, грейдер K8 `scripts/grade_promo_signals.py`, отчёт dev-петли (цитирует версию кодбука).
Версии: любое изменение конвенции = новая версия с датой и строкой в §9; строки эталона, размеченные по старой

## 1. Единица разметки и схема строки

Одна строка JSONL на **каждый коммент с текстом** — включая шум и комменты админа. Комменты **без текста** (стикер,
фото, медиа: `text.strip() == ""`) в эталон не входят: SPEC 3.19 выводит их из очереди инференса, дро считает их как
`n_wordless`, промт не размечает; знаменатель грейдера = строки эталона = комменты с текстом (dev-40: 208 − 68 = 140).
Тред = пост-корень + все комменты с `parent_msg_id == root` из замороженного архива v1 `data/raw`. Строки в порядке `msg_id`.

```
{"channel":"@VARUS_channel","thread_root":"2537","msg_id":"1689","subject_type":"chain","subject":"VARUS",
 "source":"post_context","signal_types":["жалоба"],"quote":"Немае поваги до коллективу","note":""}
```

| поле | тип | закрытый список / правило |
|---|---|---|
| `channel`, `thread_root`, `msg_id` | str | как в архиве; id — строки |
| `subject_type` | str | `chain` · `brand` · `sku` · `post` (= `aggregates.SUBJECT_TYPES`) |
| `subject` | str | каноническая форма по §3 (грейдер нормализует `promo_key`: NFC, lower, пробелы — падежи НЕ снимает) |
| `source` | str | `explicit` · `reply_context` · `post_context` (§4; пишется, грейдером не считается) |
| `signal_types` | list | подмножество {`жалоба`, `похвала`, `спрос`, `привычка`, `цена`}; `[]` = шум или нейтральное (§6) |
| `quote` | str | **подстрока** текста коммента, verbatim (§7) |
| `note` | str | ≤ 1 строка; `""` если нечего сказать |
| `unsure` | str, опц. | только своя настоящая неуверенность и почему; строка остаётся в знаменателе |

## 2. Порядок решения по комменту (всегда в этом порядке)

1. **Шум или служебный?** (§6) → `post` / `<root>` / `[]` — и дальше не думать.
2. **О чём коммент** — субъект (§3): сеть, её сервис и механика акций → `chain`; товар → `sku` или `brand` по тому,
   что названо; сам пост или канал-агрегатор → `post`.
3. **Откуда известен субъект** (§4): из самого коммента → `explicit`; из родительского коммента → `reply_context`;
   только из поста → `post_context`.
4. **Какие сигналы** (§5) — множество; сарказм читается по смыслу, не по словам (§7); нейтральное — `[]` с `note`.
5. **Цитата** — минимальный кусок текста, из которого видны сигналы (§7); `note`/`unsure` — если надо.

## 3. Субъект

- `chain` — сеть, магазин, сервис, персонал, кассы, приложение/сайт/карта, доставка, наличие в магазине, честность акций
  сети, **механика акции** (как ввести промокод, як користуватися купоном/ваучером, сканувати в додатку — §5 `спрос`).
  Субъект — та сеть, о которой коммент, **не обязательно владелец канала** («в АТБ краще» под постом VARUS → `chain` /
  `АТБ` / `explicit`). В канале ритейлера (@VARUS_channel) сам канал и его посты = сеть → `chain`.
  **Партнёр акции (v1.2)** — банк, почта, оператор доставки, платёжное приложение, организатор промо-игры, названный в посте
  или комменте (izibank, OTP банк, Укрпошта, Дія) → `chain` с именем партнёра как в посте, когда коммент о СЕРВИСЕ партнёра
  (поддержка, приложение, карта, доставка партнёра). **Условия совместной акции** (ставка кешбека, срок, честность, «поверніть
  знижку від OTP») → сеть-хозяин поста (`VARUS`), партнёр — в `note`. Партнёр никогда не `brand`.
- `brand` — названа торговая марка без конкретного товара («Яготинське завжди смачне», «Галичина краща»).
- `sku` — конкретный товар: бренд + продукт, или продукт как в посте («це молоко», «сир 45%»), в том числе указанный
  через пост («беру таке постійно» → `sku` из поста, `post_context`); товар не из поста — как назван в комменте («масло»).
- `post` — сам пост или канал-агрегатор как объект коммента: ошибка в посте («на фото неправильна ціна»), «нашо
  викладати», «канал не о скидках» — с сигналами; шум и служебные комменты — частный случай с `[]` (§6).
  `subject` = `thread_root`. Канал-агрегатор — тот, что постит акции разных сетей (v1: @msuaaaa; сеть = ритейлер,
  названный в посте: McDonald’s, KFC, Сільпо, Ашан).
  **Тред вне домена (v1.2)** — пост без ритейлера и без товара (вопрос подписчика, объявление, сбор, предупреждение;
  v1-популяция несёт такие треды из приостановленных каналов): КАЖДАЯ строка → `post` / `<root>`; сигналы — по общим правилам
  (`цена` за названную цену, `спрос` за интерес, `жалоба`/`похвала` по тону); названные учреждения (садок, школа, ліцей) —
  в `note`, не в `subject`.
- **Каноническая форма `subject`** — именительный падеж; если сущность есть в посте — в написании поста (в т.ч. апостроф:
  `McDonald’s`; латиница/кириллица как в посте: `VARUS`, даже когда коммент пишет «варусу»); если её в посте нет —
  в написании коммента, в именительном падеже. Для `sku` — «бренд + тип товара» как в тексте (`чипси Люкс`, `ПИВО BAVARIA`,
  `Щастябокс`, `МакМеню`); вкус/объём/жирность — только если в посте несколько вариантов одного товара.
  **v1.2, форма товара:** (а) товар ЕСТЬ в посте → «тип + бренд/назва» словами поста, без «ТМ», «від», «власної», кавычек,
  объёма, %, жирности и варианта, если товар один: `ескімо Varto`, `паста TUT NUT`, `нектари Наш Сік`, `Пиво світле Pilsner MOVA`,
  `морозиво М’яке`, `яйця-сюрпризи`; (б) товара в посте НЕТ → тип товара по-украински в именительном (`морозиво`, `ковбаса`,
  `оселедець`, `пиво`, `масло`), бренд — как написан в комменте (`кока кола`, `лейс`); (в) бренд, чьё имя и есть товар
  («Де кока кола», «коли акція на лейс») → `brand`. Грейдер K8 v2 сравнивает `sku`/`brand` по идентичности товара (точное
  совпадение после нормализации ИЛИ Jaccard токенов ≥ 0.5), `chain` — по id сети, `post` — точно.
  Для `chain` — имя сети как в посте; если сеть в треде не названа — хэндл канала без `@`. **Субъект строки `chain` — имя СЕТИ, никогда
  её часть или функция:** «додаток», «програма лояльності», «сертифікати», «гаряча лінія», «Scan&Go» → `VARUS`. Грейдер и агрегаты сводят
  формы имени сети к id сети из реестра (`VARUS` = `Варус` = `варус`); для `sku`/`brand` нормализация прежняя (NFC, lower, пробелы).
- **Несколько субъектов в одном комменте** — один субъект на строку: тот, к которому относится сигнал; при двух
  сигналах о разных субъектах — субъект, названный явно (explicit бьёт контекст); если оба явные — тот, с которого коммент
  начинается; второй — в `note`. Товар против сети: претензия к товару поста («кисле») — `sku`; к магазину («на полиці
  нема», «пробили дорожче», «у вас не додають відгуки») — `chain`.
- Сравнение цены с другой сетью («в АТБ по 39») — субъект остаётся товаром поста (`sku`, `цена`), конкурент — в `note`.

## 4. Источник субъекта (`source`)

- `explicit` — субъект виден из текста коммента: название сети/бренда/товара в любом падеже («варусу», «в Ашані»,
  «масло»), или обращение к сети/каналу («ви», «у вас», «ваш магазин», «канал»). Указательное «це/таке/той бокс» —
  **не** explicit (указывает на пост → `post_context`).
- `reply_context` — субъект ясен только из родительского коммента (ответ «так, теж кисле було», «Теж саме питання»).
  В архиве v1 `reply_to_msg_id` пуст: родитель выводится по обращению (@, имя, цитата) или по последовательности,
  когда текст явно ответ.
- `post_context` — субъект ясен только из поста («дорого», «є в наявності?», «беру постійно», «що в тому боксі?»).
  Шум — всегда `post_context`.

## 5. Типы сигналов (множество на коммент)

| тип | что это | маркеры (укр./рус.) | не относится |
|---|---|---|---|
| `цена` | суждение или вопрос, объект которого — цена, скидка, акция: уровень, динамика, честность/правильность, сравнение, условия | «дорого», «дешево», «нормальна ціна», «раніше було 45», «стара ціна намальована», «в АТБ по 39», «це з карткою?», «89 грн за пачку?!», «ціна на фото вірна» | цифра поста повторена без оценки |
| `спрос` | интерес к предложению: намерение купить; вопрос о наличии, месте, сроке, содержимом; просьба завезти/зробити акцію; вопрос, как воспользоваться акцией | «куплю», «треба взяти», «де купити?», «в якому Ашані?», «коли у всіх маках?», «до коли діє?», «що в боксі?», «як ввести промокод?», «як користуватися купоном?» | «більше не куплю» (→ `жалоба`) |
| `привычка` | заявленная регулярность покупки/потребления — прошлая или текущая; нужно **слово регулярности** | «беру постійно», «завжди купуємо», «щотижня», «регулярно», «років 10 п'ю тільки це» | счёт покупок без регулярности («сьогодні брали», «перший раз… вчора», «декілька разів купувала»), разовое намерение (→ `спрос`) |
| `похвала` | позитивная оценка субъекта: вкус, качество, сервис, выгодность акции | «смачне», «очень вкусное», «найкраще молоко», «у вас завжди чисто», «дякую за акцію на молоко», «класна ціна» | голое «дякую», эмодзи (→ шум) |
| `жалоба` | негативная оценка или претензия: качество, сервис, наличие, обман/несоответствие, отказ от покупки, сарказм с негативным смыслом | «кисле», «отвратительное», «каси не працюють», «приїхала — нема», «на фото неправильна ціна», «торгівля повітрям», «більше не куплю», «занадто довго на стадії розробки» | нейтральный вопрос (→ `спрос`/`цена`), нейтральное пояснение (→ `[]`) |

Субъект вопроса `спрос`: наличие/место/срок/содержимое товара → **товар** (`sku`/`brand`, магазин — в `note`); механика
акции, сроки/условия акции в целом, кешбек, доставка, магазин в городе («У Вінниці є ваш магазин?») → **сеть** (`chain`);
просьба к каналу-агрегатору о промо другой сети («Нових знижок атб ще не виклали?») → `chain` той сети, `explicit`.
Вопрос-претензия («Что с бонусами, у меня ноль») — `жалоба`, не `спрос`. Благодарность с предметом («дякую за вашу
працю», «дякую за акцію на молоко») — `похвала` к адресату; голое «дякую/спасибо ❤️» — шум. Типичные пары: «дорого» → `цена`+`жалоба`;
«500 грн за картонку» → `цена`+`жалоба`; «супер ціна, дякую» → `цена`+`похвала`; «коли буде знижка на X», **«а X де?», «де кока кола 😭»,
«чекаємо нових акцій» (v1.2: вопрос о наличии СКИДКИ на товар, не товара)** → `спрос`+`цена`; **суждение о цене как
об индикаторе качества (v1.2, слово оператора 05.09: «Ковбаса за 19 це опасно», «за такі гроші вона і має бути супер») → только `цена`** —
это цена качества, не претензия; `жалоба` добавляется лишь при претензии к сети или к факту (порча, обман, «дорого», «в АТБ дешевше»);
«беру постійно, смачне» → `привычка`+`похвала`; «брала роками, тепер зіпсувалось» → `привычка`+`жалоба`; «на фото
неправильна ціна» → `жалоба`+`цена` (`post`); «приїхала за акцією — товару нема» → `жалоба` (`chain`) + `спрос`, если сказано,
что хотел купить. Тон определяется **по отношению к субъекту строки**: «в АТБ дешевше» — `цена`+`жалоба` к товару поста.

## 6. Шум, служебные и нейтральные комменты

- **Шум** → `post` / `<root>` / `post_context` / `[]`: только эмодзи или реакция («💗», «🔥», «😂»); приветствия, голое
  «дякую»; теги/упоминания без текста; спам, боты, реклама; оффтоп без субъекта из треда («Слава ЗСУ» под постом о сборе).
  Эмодзи-реакция — шум независимо от валентности. (Коммент вовсе без текста — не строка эталона, §1.)
- **Комменты админа/канала** → `post` / `<root>` / `[]`, `note: "admin reply"` (ответ пользователю, `source: reply_context`)
  или `note: "admin addendum"` (дополнение к посту, `post_context`). Признаки: стабильный `sender_anon_id` админа канала
  (v1: VARUS `2fa2b7…`, msuaaaa `58805a…`) и форма («Розуміємо вас», «передали», «напишіть у чат @varusua_bot», «Фото вже прибрали»).
  v1.1: рендер промта помечает комменты аккаунта канала как `[admin]` (id из реестра) — правило применяется механически, модель не гадает.
- **Нейтральное** (не шум, но и не сигнал): справка, пояснение, ответ по факту, уточнение без оценки и намерения, В КОТОРОМ субъект
  назван или очевиден из поста («так працює система», «Або з 9 числа» про МакМеню, «Працює 5%» про кешбек) → субъект как есть,
  `signal_types: []`, `note: "neutral: …"`. **Реплика другому комментатору, которая ничего не называет и не несёт сигнала** («А що не
  так?», «Да», «А то всьо за@бало», «Це типу домах?») → `post` / `<root>` / `[]` (v1.1: раньше такие строки наследовали субъект вопроса).
  **v1.2:** сюда же реплика-выпад другому комментатору в споре, даже если в ней названа сеть без оценки самой сети («Ще один комік,
  ідіть у АТБ», «Я не працюю у Варусі, адресуйте свій негатив за адресою», «Підтримую, не пускайте!») → `post` / `[]`; а вот
  «Ми то підемо куди нам треба» (отказ от покупок) → `chain` / `жалоба`.

## 7. Ирония, цитата, границы

- **Сарказм/ирония** размечаются по смыслу: «чудова "знижка" 🤡» → `цена`+`жалоба`; «Розкішно. Пів дня без світла, зате
  свічки зі знижкою» → `жалоба` (v1.2: синтетический пример вместо near-quote dev-коммента); `note: "irony"`.
- `quote` — минимальный связный кусок, содержащий маркеры всех сигналов строки (если они далеко — кусок первого
  сигнала); копипаст с опечатками и эмодзи, без правок; шум — весь текст, если ≤ 40 символов, иначе первая фраза.
- Вопрос без оценки — только `спрос` или `цена` по объекту вопроса; оценка + вопрос — оба.
- `unsure` — когда две разметки одинаково защитимы; писать, какие именно («sku vs chain», «irony vs neutral»).

## 8. Самопроверка партии (перед снятием «жду метки»)

Каждая строка — валидный JSON с ровно этими полями (+ опц. `unsure`); enum-поля в списках §1; `msg_id` существует в
треде и **все комменты с текстом** покрыты (счётчик = `n_comments − n_wordless` дро), ни одной строки на коммент без
текста; `quote` — непустая подстрока текста коммента; `subject == thread_root` для `post`; шум — `[]`; ни одного id из
`draw.*.holdout` (для dev-40) / ни одного id из `promo_threads_draw_2.json :: holdout` (для dev-2, v1.2).
